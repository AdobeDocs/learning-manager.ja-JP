# NRPSのLTIサポート

## 概要

Adobe Learning ManagerがLearning Tools Interoperability(LTI)1.3ツールとして機能する場合、Names and Role Provisioning Services(NRPS)仕様をサポートします。 学習者が外部の学習管理システム（プラットフォーム）からLearning Managerを起動すると、Learning Managerはプラットフォームから学習者のメンバーシップレコードを取得します。 次に、そのレコードのカスタム属性（部門IDや従業員IDなど）を、学習者のプロファイルにアクティブフィールドとしてコピーします。

## ユースケース

* **学習者プロファイルを自動的に強化します。** 部署、従業員ID、カスタムメタデータなどの属性をプラットフォームからLearning Managerに読み込みます。手動でデータを入力する必要も、個別に読み込む必要もありません。
* **学習者の出所を分析します。** 国や都市などの場所の属性をキャプチャして、学習者の出身地域の写真を作成します。 生成されたプロファイルフィールドをLearning Managerでの分析に使用します。
* **プロファイルデータをソースプラットフォームに合わせて維持します。** プラットフォームは依然として真実の源です。 Learning Managerでは、学習者が起動するたびに値が更新されます。
* **1つのアカウントで複数のプラットフォームをサポートします。** 名前空間プレフィックスは、プラットフォームが同じ属性名を使用している場合でも、異なるプラットフォームの属性を個別に保持します。

NRPSカスタムフィールド同期を使用すると、Learning Managerの起動時に次の処理が行われます。

1. プラットフォームがNRPSをサポートしていることを検出します。
2. プラットフォームから、起動時の学習者のメンバーシップレコードを要求します。
3. そのレコードからカスタム属性を抽出します。
4. 属性を学習者のプロファイルにアクティブフィールドとして書き込みます。 各フィールド名には`<namespace>`というプレフィックスが付いているため、異なるプラットフォームの属性が競合することはありません。
5. Learning Managerは、割り当ておよび評価サービス(AGS)に既に使用しているOAuth 2.0クライアント資格情報トークンを再利用します。 新しいトークンエンドポイントを構成する必要はありません。

>[!NOTE]
>
>NRPSは、LTI Advantageのオプション仕様です。 NRPSとカスタム属性のサポートは、プラットフォームによって異なります。 この機能を使用する前に、プラットフォームにNRPS 2.0が表示されていることを確認してください。

## 主な機能

* **NRPS要求のサポート：** Learning Managerは、LTI 1.3を起動するたびにNRPS要求を確認します。 申請がない場合、エラーも学習者への影響もなく、通常どおり起動が続行されます。
  * この要求は、次の情報を提供します。
    * **メンバーシップエンドポイント：** `context_memberships_url `学習者がALMを起動したコースまたは学習コンテキストのサービスURLを識別します。
    * **サポートされているバージョン：** `service_versions`には、そのエンドポイントで利用可能なNRPSバージョンが一覧表示されます。
      この機能はNRPS 2.0をサポートしています。
  * **共有トークンインフラストラクチャ:** Learning Managerは、既存のAGSトークンリクエストにNRPSスコープを追加し、既存の登録別トークンキャッシュを再利用します。
* **カスタムパラメーターを学習者プロファイルに同期**
  * **名前空間のプレフィックスが付いたアクティブなフィールド：**&#x200B;各カスタム属性は、`<namespace>_<field_name>`という名前のアクティブなフィールドにマップされます。
  * **フィールドの自動作成：**&#x200B;一致するアクティブフィールドが存在しない場合、Learning Managerはタイプ&#x200B;**Text**&#x200B;およびステータス&#x200B;**Active**&#x200B;を持つフィールドを作成します。
  * **信頼できる情報源としてのプラットフォーム：** Learning Managerは、既存のプロファイル値をプラットフォームからの最新の値で上書きします。 学習者および管理者はこれらのフィールドを編集できません。
  * **非ブロック動作：** NRPSエラーが発生しても、学習者は学習コンテンツを起動できません。
  * **カスタム属性の複数のソース：** Learning Managerは、NRPSエンドポイントおよびLTI起動トークン内のカスタムパラメーターからカスタム属性を読み取ることができます。 [起動トークンのカスタム属性](#custom-attributes-in-the-launch-token)に関する詳細をご覧ください。

## サポートされる構成

| アイテム | サポート |
|----------------------------------------------------------------|--------------------------------------------------------------------------|
| Learning Manager役割 | LTI 1.3ツール |
| LTIバージョン | LTI 1.3 |
| NRPSサービスバージョン | 2.0 |
| プラットフォーム（仕様に準拠したカスタムフィールド形式） | Moodle, D2L Brightspace, Blackboard (Anthology), Sakai |
| カスタムフィールドタイプ | テキスト |
| トリガー | 各LTI 1.3の発表 |

プラットフォームのサポートは、NRPSメンバーレコードで使用されるカスタムフィールドのシリアル化パターンによって異なります。 複数のパターンが共存する場合がありますが、Learning Managerではアクティブリリースでサポートされているパターンのみが処理されます。

## 動作の仕組み

### 起動フロー

1. 学習者がプラットフォームからLearning Managerを起動します。
2. Learning Managerは、LTI 1.3起動トークン内のNRPS要求を読み取ります。 要求にNRPSサービスバージョン2.0がリストされている場合、Learning ManagerではセッションおよびLTIコンテキスト（コース）の`context_memberships_url`が保存されます。
3. Learning Managerは、NRPSスコープ`https://purl.imsglobal.org/spec/lti-nrps/scope/contextmembership.readonly`を含むアクセストークンを要求します。
4. Learning Managerはベアラートークンを使用して`context_memberships_url?rlid=<lti_user_id>`を呼び出し、起動した学習者のレコードを取得します。 プラットフォームが`rlid`フィルターを無視して名簿の全文を返した場合、Learning Managerは`user_id`までに学習者を検索します。
5. Learning Managerは、レコードからカスタムフィールドを抽出します。
6. Learning Managerは各カスタムフィールドをアクティブフィールドにマッピングし、値を学習者のプロファイルに書き込みます。
7. また、カスタムパラメーターがALM識別可能なフィールド`ALMfield`で事前に固定されている場合、ALMは、ツールの起動時に学習者プロファイルに同期するカスタムパラメーターの抽出もサポートしています。

### カスタムフィールド形式

NRPS 2.0仕様では、カスタムデータをメンバレコードの`message`配列として定義します。 Learning Managerは、そのアレイ内のLTIカスタム要求からカスタムデータを読み取ります。 このリリースのLearning Managerでは、仕様に準拠したパターンS表現がサポートされています。

```json
{
  "user_id": "abc123",
  "message": [
    {
      "https://purl.imsglobal.org/spec/lti/claim/custom": {
        "department": "Engineering",
        "employee_id": "E4567"
      }
    }
  ]
}
```

### 起動トークン内のカスタム属性

プラットフォームは、LTI起動トークンでカスタムパラメーターとしてカスタム属性を送信することもできます。 Learning Managerは、起動トークンとNRPSエンドポイントの両方から属性を収集し、学習者プロファイルに保存します。

起動トークンの属性の場合、パラメーター名はLearning Managerに必要なプレフィックス`almfield-`で始まる必要があります。 接頭辞が付いていない場合、Learning Managerはこれらのパラメーターを他のカスタムパラメーターと区別できず、読み込みません。 NRPSエンドポイントから取得された属性には、このプレフィックスは必要ありません。 この接頭辞は、学習者のアクティブなフィールドに同期するフィールドを識別するためにALMの起動トークンにカスタムパラメーターが読み込まれる場合にのみ必要です。

>[!NOTE]
>
>プラットフォームでカスタムパラメーターを設定する前に、Learning Managerの担当者と正確な必要なプレフィックスを確認します。

### アクティブなフィールドの命名とマッピング

Learning Managerでは、アクティブフィールド名を`<namespace>_<field_name>`として構築します。 たとえば、名前空間`https://purl.imsglobal.org/spec/lti/claim/custom`の`department`フィールドは`https://purl.imsglobal.org/spec/lti/claim/custom_department`になります。

Learning Managerでは以下のルールが適用されます。

* **名前の長さ：**&#x200B;名前がアクティブなフィールド名の文字制限を超えている場合、Learning Managerは最初に名前空間部分を短縮し、フィールド名を維持します。
* **名前の競合：**&#x200B;短縮後、Learning Managerは別のソースからの既存のアクティブフィールドとの競合を確認します。 競合がある場合は、一意の名前が見つかるまで短縮の長さを調整します。 一意の名前が見つからない場合は、フィールドをスキップし、エラーをログに記録します。
* **一致：**&#x200B;フィールド名の一致では、大文字と小文字は区別されません。
* **既存の有効なフィールド:** Learning Managerは値を学習者のプロファイルに書き込みます。
* **既存の無効なフィールド:** Learning Managerはエラーをログに記録せずにフィールドをスキップします。
* **既存のフィールドがありません：** Learning Managerは、ステータスが&#x200B;**アクティブ**&#x200B;の&#x200B;**テキスト**&#x200B;フィールドを作成します。

### プロファイルへの値の書き込み

* Learning Managerは起動のたびに、NRPSデータを取得し、解決されたすべてのカスタムフィールド値を起動中の学習者のプロファイルに書き込みます。 他の学習者プロファイルは変更されません。
* フィールドに既に値が設定されている場合、Learning Managerはその値をプラットフォームからの最新の値で上書きします。
* プラットフォームの値が空またはnullの場合、Learning Managerでは既存のプロファイル値が維持されます。
* 1つのフィールドへの書き込みに失敗しても、他のフィールドの起動や書き込みはブロックされません。
* Learning Managerでは、可能な場合、同じ起動トランザクションでフィールドの更新を適用します。
* 学習者は、プロファイルページでNRPSのフィールドを編集することはできません。また、管理者は、学習者に代わってこれらの値を編集することもできません。

## NRPSカスタムフィールド同期の設定

### 前提条件

* プラットフォームがLTI 1.3ツールとしてLearning Managerに登録されている。 この機能は、LTI 1.1またはLTI 1.2をサポートしていません。
* お使いのプラットフォームは、NRPSサービスバージョン2.0をサポートし、仕様に準拠した`message`フォーマットでカスタム属性を表示します。
* LTI起動トークンに`namesroleservice`要求が含まれています。
* 要求は`context_memberships_url`を提供します。これは、コース固有のNRPSエンドポイントを識別します。
* 要求の`service_versions`値に`2.0`が含まれています。
* プラットフォームのツール登録に対する管理者アクセス権がある。

### Learning ManagerへのNRPS範囲の付与

NRPSスコープを含む新しい登録では、Learning Managerで追加の設定を行う必要はありません。

NRPS範囲を含む新しい登録は、Learning Managerでそれ以上変更することなく機能します。 既存の登録の場合、プラットフォーム側でツール登録を更新する必要があります。

>[!NOTE]
>
>トークンのエンドポイント、クライアントID、秘密キーをLearning Managerで変更する必要はありません。 既存のAGS設定が再利用されます。 プラットフォームがNRPSスコープを付与していない場合、Learning ManagerはAGSや起動に影響を与えずにNRPSをスキップします。

### プラットフォームでの学習者属性の表示

プラットフォームは、共有する学習者属性を制御します。 正確な手順は、プラットフォームによって異なります。 例えば、Moodleでは次のようになります。

1. LTI 1.3を使用して、Learning Managerを外部ツールとして追加します。
2. プラットフォームがツールを使用して学習者情報を共有できるようにするプライバシー設定を有効にします。
3. 送信するカスタム属性を定義します。 プラットフォーム変数または定義済みの値を使用できます。
4. また、起動トークンで属性をカスタムパラメーターとして送信する場合は、各パラメーター名にLearning Managerが必要とするプレフィックスを追加します。

>[!NOTE]
>
>学習ユースケースに必要な属性のみを表示します。 Learning Managerでは、プラットフォームを真実の源と見なしており、このリリースでは個別の同意やプライバシー管理は提供していません。

### 同期を確認する

1. テスト学習者として、プラットフォームからLearning Managerを起動します。
2. 起動が正常に完了したことを確認します。
3. Learning Manager管理者アプリで、アクティブフィールドページを開きます。
4. フィールドが名前空間のプレフィックス、種類&#x200B;**Text**、状態&#x200B;**Active**&#x200B;で表示されていることを確認してください。
5. テスト学習者のプロファイルを開き、値がプラットフォームと一致していることを確認します。
6. NRPSから取得されたフィールドが読み取り専用であることを確認します。 学習者も管理者も、同期された値を手動で編集することはできません。
7. 空でないソース値を変更した後に再起動し、Learning Managerによって既存のプロファイル値が最新のNRPS値で上書きされることを確認します。

>[!TIP]
>
>フィールドが存在するが無効の場合、Learning Managerはそのフィールドへの書き込みを行いません。 フィールドに値を入力する場合は、このフィールドを有効にします。

## エラー処理とログ

NRPSの問題で、Learning Managerが学習者をブロックすることはありません。 再試行は行われません。 障害をログに記録し、その起動に対するNRPSの同期をスキップします。 次回の起動が再試行されます。

| 条件 | 結果 |
|------------------------------------------------------------------|-------------------------------------------------------|
| 起動トークンにNRPS要求が存在しません | NRPSはスキップされます。 起動が続行されます。 |
| NRPSサービスバージョン1.0のみが存在します | NRPSはスキップされます。 起動が続行されます。 |
| トークン要求が失敗するか、プラットフォームがNRPS範囲を許可しない | NRPSはスキップされます。 AGSと起動は影響を受けません。 |
| NRPSコールの失敗（タイムアウト、4xx、または5xx） | エラーが記録されます。 起動が続行されます。 |
| NRPS応答に学習者が見つかりません | フィールドの同期はスキップされます。 起動が続行されます。 |
| NRPS応答にカスタムフィールドがありません | フィールドの同期はエラーなしでスキップされます。 |
| フィールド名の競合を解決できません | このフィールドはスキップされ、エラーがログに記録されます。 |
| 1つのフィールドへの書き込みが失敗する | その他のフィールドは引き続き書き込まれます。 起動が続行されます。 |

各ログエントリには、タイムスタンプ、プラットフォーム登録ID、学習者ID、失敗理由が含まれます。 Learning Managerのシステム管理者は、ログにアクセスできます。

## メモ

* 起動した学習者の記録のみが同期されます。 Learning Managerでコース名簿全体が同期されません。
* NRPSサービスバージョン2.0のみがサポートされています。
* 同期されたすべてのフィールドの種類は&#x200B;**Text**&#x200B;です。 Learning Managerは値からタイプを推測しません。 数値、日付、およびブーリアンフィールドの種類はサポートされていません。
* Learning ManagerはLTIツールとして機能します。 NRPSプラットフォームとして機能せず、他のツールに名簿のエンドポイントを提供しません。
* カスタムフィールドの同期は、LTIの起動時に行われます。
