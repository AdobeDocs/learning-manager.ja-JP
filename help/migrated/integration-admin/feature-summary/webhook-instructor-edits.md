# インストラクターによるLOインスタンス編集のWebhookイベント

Adobe Learning Managerには、インストラクターが指導するコースのセッションなどの学習目標(LO)インスタンスが変更された場合に、外部システムに通知するwebhookイベントが用意されています。 以前は、管理者または作成者がLOインスタンスを変更したときにのみ、これらのイベントがトリガーされていました。 Webhookイベントは、インストラクターがセッションの詳細を編集したときにもトリガーされるようになりました。

これらのイベントを使用すると、メールサービス、カレンダー、レポートツール、分析プラットフォームなどの外部システムを、インストラクターの変更に応じて最新の状態に保つことができます。 例えば、セッション時間が変更されたときに学習者に通知することができます。

インストラクターによる編集では、既存の学習オブジェクトインスタンスの変更イベントが使用されるため、新しいイベントタイプは導入されません。

>[!NOTE]
>
>インストラクターの編集によりwebhookがトリガーされるのは、アクティブなwebhookが学習オブジェクトインスタンスの変更イベントをサブスクライブしている場合のみです。 [統合管理者としてWebhookを作成および管理する](/help/migrated/integration-admin/feature-summary/webhooks.md#create-manage-webhooks)方法について説明します。

## サポートされているインストラクターの編集

Webhookイベントは、インストラクターが次のセッションの詳細のいずれかを編集するとトリガーされます。

* セッションのタイミング

* クレジット

* タイムゾーン

* 会場

* 登録数の上限

* キャンセル待ちの制限

* 提出を許可

## Webhookペイロード構造

各Webhookリクエストには、次のトップレベル構造が含まれています。

```json
{
  "accountId": 1234,
  "events": [
    {
      "eventId": "121da98-ab8d-43e9-b671-e79131cd69dc",
      "eventName": "LEARNING_OBJECT_INSTANCE_MODIFICATION",
      "timestamp": "2024-11-08T03:49:52.000Z",
      "eventInfo": "1235603297000-040649-741781-0",
      "data": {
        "loInstanceId": "course:12324298_14453691",
        "loId": "course:12324298",
        "loType": "course"
      }
    }
  ]
}
```

LOインスタンスを変更したユーザーに関係なく、同じ構造が使用されます。 ペイロードには、インストラクター、管理者、作成者のいずれが変更を行ったかが示されません。

タイムゾーン、登録制限、キャンセル待ちの制限など、セッションの詳細をインストラクターが変更すると、webhookにより、このイベントがリスナーURLに送信されます。 イベントを使用して、最新のセッション詳細を取得し、学習者に通知したり、外部システムを更新したりします。

## 更新されたセッションの詳細を取得する

Webhookイベントは、変更されたLOインスタンスを識別します。 更新されたセッションの詳細を取得するには、イベントから`loId`を使用してLearning ManagerパブリックAPI (Prime API)を呼び出します。

```http
GET /primeapi/v2/learningObjects/{loId}
```

応答で`loInstanceId`に一致するインスタンスを見つけて、システムに格納されているデータと比較します。

## Webhookイベントとの統合の構築

これらのwebhookイベントは、次の場合に使用できます。

* 日付、時刻、タイムゾーン、会場などのセッションの詳細が変更された場合、外部の電子メールまたはメッセージングサービスを介して学習者の通知を送信します。

* 外部のカレンダー、レポート、または分析システムとセッションデータを同期します。

* セッションの登録制限またはキャンセル待ちの制限が変更されたときに容量の変更を追跡します。

* LOおよびインスタンス識別子と共に`eventId`、`timestamp`および`eventInfo`をログに記録して、監査証跡を管理します。

少なくとも、webhookハンドラーは次のことを行う必要があります。

* ペイロードを検証し、`events[]`を解析します。

* `eventName`を使用して、学習オブジェクトインスタンスの変更イベントを識別します。

* `loId`と`loInstanceId`を使用してシステム内の対応するレコードを検索し、パブリックAPIを呼び出して現在のセッションの詳細を取得します。

* 同じイベントが複数回配信される場合に、重複処理を防ぐには`eventId`を使用します。

インストラクター、管理者、作成者が行った編集に対して同じイベントが送信されるため、統合が以前よりも頻繁に受け取る可能性があります。 通知を送信する前に、取得されたセッションの詳細とシステム内のデータを比較します。 関連する詳細が変更された場合にのみ、学習者に通知されます。
