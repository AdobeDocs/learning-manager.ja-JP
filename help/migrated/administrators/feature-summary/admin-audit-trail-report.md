# 管理者監査追跡レポート {#adminaudittrailreport}

アカウントの基本、詳細、統合設定に加えられた設定変更のレポートを生成します。このレポートには、各変更を行ったユーザー、日時、変更前後の値が含まれます。

## レポートのキャプチャ

管理者監査追跡レポートには、構成変更の履歴が記録されるので、次の項目を決定できます。

- 変更したユーザー
- 変更が行われた日時
- 変更前の設定
- 変更後の設定

このレポートには、次の変更が含まれます。

- **基本**&#x200B;の設定
- **詳細設定**&#x200B;の設定
- **統合**&#x200B;設定

このレポートは追加専用です。新しい変更レコードは時間の経過とともに追加され、以前に記録されたエントリは削除されません。 これにより、現在の値だけでなく、複数の変更に対する設定の履歴全体を確認できます。

レポートは、レポート権限を持ち、ユーザーグループに対するフルアクセス権を持つすべてのユーザーが使用できます。 これには、完全な管理者と、レポートアクセス権を付与されているカスタム管理者が含まれます。

>[!NOTE]
>
>レコードは、2026年9月のアップデート112以降で利用できます。 この更新の前に行われた変更は、レポートに含まれません。 [リリースノート](/help/migrated/release-note/release-notes.md)アップデート112を参照してください。

## このレポートがコンプライアンスの重要事項である理由

規制の厳しい業界に属する組織では、電子記録を処理するシステムに対する構成変更が追跡され、帰属可能で、保持されていることを示す必要が頻繁にあります。 管理者の監査追跡レポートでは、各変更に対して個人、設定、時間、および前後の値を識別することで、これらの要件をサポートします。

>[!NOTE]
>
>このレポートは、組織のコンプライアンス活動をサポートします。 アドビは、それ自体で、特定の規制または基準に準拠していることを証明するものではありません。

## 管理者監査追跡レポートの生成

1. Adobe Learning Managerに管理者としてログインします。
2. 左側のナビゲーションで、**管理**/**レポート**/**カスタムレポート**&#x200B;を選択します。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report1.png)

3. 下にスクロールして、**管理者監査証跡**&#x200B;を選択します。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report2.png)

4. **範囲の選択**:レポートする期間を選択してください – **過去1週間**、**過去1か月**、または&#x200B;**日付の選択**。 **日付の選択**&#x200B;を選択する場合は、**開始日**&#x200B;と&#x200B;**終了日**&#x200B;を入力します。
5. **設定の種類を選択**: **すべて選択**、**基本**、**統合**&#x200B;または&#x200B;**詳細**&#x200B;を選択します。

   このレポートによって追跡された、基本、統合、詳細にわたる設定の完全な一覧を表示するには、**設定の一覧をダウンロード**&#x200B;を選択します。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report6.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report3.png)

6. 「**生成**」を選択します。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report4.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report5.png)

変更内容を含む`.csv`ファイルがブラウザーのダウンロードフォルダーにダウンロードされます。 レポートの作成には数分かかる場合があります。処理中もAdobe Learning Managerを引き続き使用できます。 レポートの準備が整う前にブラウザーウィンドウを閉じると、次にログインしたときにダウンロードが開始されます。

## このレポートの一般的な用途

- **予期しない設定の変更を調査する** – 仮定に頼るのではなく、変更の内容、変更日時、変更者を確認します。
- **複数の管理者によって行われた変更の確認** ：各管理者に個別に連絡するのではなく、特定の期間のレポートの範囲にあるすべての構成アクティビティの統合ビューを生成します。
- **承認された構成の変更を確認する** – 必要な管理者が必要な期間内に変更を加えたこと、および新しい値が承認されたものと一致していることを確認します。
- **複数の変更にわたる設定の履歴を比較する** - [**リビジョン**]列を使用して、特定の設定が変更された回数を確認し、記録された各値を順に確認します（後で行った変更が以前の値を復元したかどうかも含みます）。
- **コンプライアンスレビューをサポート** – 管理およびコンプライアンスレコードの一部として、レビュー中の期間のレポートを生成します。
- **ポリシーの変更後に設定を確認する** – 意図した構成の更新が一貫して適用されたことを確認し、予期せず発生した変更を特定します。
- **過去の管理記録を保持** – 組織の記録管理の方法に従ってレポートをダウンロードおよび保持します。

## レポート列の参照

ダウンロードされた`.csv`ファイルには、次の列が含まれています。

| 列 | 説明 |
|---|---|
| **イベントID** | この特定の変更レコードの一意の識別子です。 |
| **タイムスタンプ(UTC)** | 変更が行われた日時（協定世界時）。 |
| **電子メール** | 変更を行った管理者の電子メールアドレス。 |
| **UUID** | 変更を行った管理者の一意の識別子。 アカウントレベルでUUIDが有効になっている場合にのみ入力されます。 |
| **管理者名** | 変更を行った管理者の表示名。 |
| **イベントの種類** | 記録されたイベントのカテゴリ – `Modify`、`Create`、または`Delete`など。 |
| **アクションの種類** | 設定に対して実行されたアクションの種類です（例： `CREATE_SETTING`、`UPDATE_SETTING`、または`DELETE_SETTING`）。 |
| **オブジェクトの種類** | 変更された設定オブジェクトまたは構成オブジェクト。 |
| **オブジェクトID** | 変更された特定の設定または構成オブジェクトの一意の識別子。 |
| **前の値** | 変更前の設定値。 （削除された設定の場合、削除前に存在した値が表示されます）。 |
| **新しい値** | 変更後の設定の値。 （削除された設定の場合、これは空白です）。 |
| **リビジョン** | イベントの記録時にこの特定のオブジェクトIDが変更された回数。 オブジェクトに対して記録された最初の変更は1から始まります。 |

>[!TIP]
>
>期間中に削除されたすべての設定を検索するには、**アクションの種類**&#x200B;が`DELETE_SETTING`であるダウンロード済みファイルをフィルターします。

## プログラムを使用してこのレポートにアクセス

管理者監査追跡レポートは、管理アプリから手動で生成するのではなく、ジョブAPIを使用してプログラムで取得できます。 これは、定期的な書き出しをスケジュールする場合や、レポートをダウンストリームの監視またはアラート・システムに送る場合に便利です。 [ジョブAPI管理者監査追跡レポート](/help/migrated/api-changes-sep-2026.md#job-api-for-admin-audit-trail-report)を参照してください。

## 制限

- **ローカライズ**:レポートの内容はローカライズされていません。 レポートは、アカウントに設定されているロケール設定に関係なく、デフォルトのアカウント言語で生成されます。
- **変更の理由**:レポートには、変更が行われた理由が記録されません。 関連する変更リクエスト、承認、またはビジネス上の理由を個別に保持する。

## ベストプラクティス

- 疑わしい変更または計画された変更を対象とする日付範囲を選択します。
- 影響を受ける設定領域が不明な場合は、**すべて選択**&#x200B;してください。
- 各エントリの&#x200B;**前の値**&#x200B;と&#x200B;**新しい値**&#x200B;の列を比較します。
- **管理者名**&#x200B;列と&#x200B;**タイムスタンプ**&#x200B;列を使用して、変更を承認済みの作業または内部レコードに関連付けます。
- 組織で変更に関する文書化された説明が必要な場合は、関連する変更リクエスト、承認またはビジネス・ジャスティフィケーションを個別に保持します。

## トラブルシューティング

**特定の日付より前のレコードは表示されません**
レコードは、アップデート112（2026年9月）以降でのみ使用できます。 その更新前に行われた変更は、レポートに含まれません。 [リリースノート](/help/migrated/release-note/release-notes.md)を参照してください

**一部またはすべてのレコードのUUID列が空です**
UUID列は、アカウントレベルでUUIDが有効になっている場合にのみ入力されます。 有効になっていない場合、この列は表示されません。

**カスタムの管理者の役割がありますが、このレポートが見つかりません**
カスタム役割にレポート権限とユーザーグループへのフルアクセス権が付与されていることを確認します。 必要に応じて、アカウント所有者または完全な管理者に連絡して、このアクセス権をリクエストしてください。
